# ワイヤ曲率計測 GUI

青背景で撮影したワイヤ曲げ動画から、伸びているワイヤの中心線に沿った
**局所曲率 κ(s) = 1/R** を画像処理で求めるデスクトップアプリ。

## セットアップ

```bash
pip install opencv-python numpy scipy scikit-image matplotlib
# Tkinter は標準（Linuxで無い場合: sudo apt install python3-tk）
python wire_curvature_gui.py
```

同じフォルダに `experiment_k20.mp4` があれば起動時に自動読み込みします。

## 処理パイプライン

1. **分離** — **色分離(既定)**: 各画素の最小チャネル `min(B,G,R)` を閾値化する。銀/白ワイヤは全チャネルが高いので大きく、彩度の高い青背景は R が低いので小さい。**明暗ムラに強く、暗いワイヤ部分も背景と分離できる**ため断片化しにくい。従来のグレースケール輝度も選択可(チェックOFF)。
2. **細線抽出** — 太い塊(機構ヘッド・センサ)を形態学的オープニングで除去し、細い線構造のみ残す。**膨張で断片を橋渡し**して(細線は後段の skeletonize で中心線化されるため中心線は保たれる)、最長連結成分をワイヤとして採用。
3. **中心線化** — `skeletonize` で1px化。**端点があれば** BFS で端点間の最長パスに順序付け、**端点の無い閉ループはサイクルを一周たどる**(周期スプライン用)。
4. **平滑化** — 弧長でパラメータ化し3次平滑化スプライン `splprep` を当てはめ(閉ループは `per=1` の周期スプライン)。
5. **曲率** — κ(s) = (x′y″ − y′x″) / (x′²+y′²)^{3/2} を弧長に沿って計算(**符号付き**。表示側で符号付き/絶対値を切替)。
6. **校正** — 画像上で既知寸法の2点をクリック→ mm 入力で px→mm 換算。κ[1/mm]・R[mm] 表示。

## 操作

抽出パラメータは「数字を勘で動かして解析ボタン」ではなく、**赤いマスクを見ながら
リアルタイムに合わせる**設計。マスクがワイヤにきれいに乗ったら『解析』を押す。

| 操作 | 内容 |
|---|---|
| 動画を開く | mp4/avi/mov/mkv を読み込み。読込時にOtsuで閾値を自動初期化 |
| 画像を開く | png/jpg/bmp/tif/webp 等の静止画を1枚読み込み(日本語パス対応)。そのまま解析・校正・CSV/注釈画像の書出しが可能。フレームスライダと全フレーム一括は無効 |
| フレームスライダ | フレーム移動 |
| ROI(画像上でドラッグ) | 解析範囲を指定。自由に伸びた弧を囲むと安定。「全体にリセット」あり |
| **ライブプレビュー** | ON時、スライダーを動かすと抽出マスクを赤の半透明で即時表示 |
| **青背景を色で分離** | 既定ON。最小チャネルで青背景と銀ワイヤを分離。**細い/暗いワイヤが断片化するときに有効**。無彩色背景や色分離で不都合なときはOFFでグレースケールに戻す |
| **明るさ自動(Otsu)** | ROI内の分布(色分離ONなら最小チャネル)から閾値を自動設定 |
| **ワイヤをクリックで調整** | ワイヤ上を1回クリック→その明るさから閾値を推定 |
| ① 明るさしきい値 | これより明るい画素をワイヤとみなす。色分離ON時は最小チャネルに対する閾値(旧「閾値」) |
| ② 太い部分を消す | ヘッド/センサの太い塊を除去(旧「塊除去」) |
| ③ 線をつなぐ | 途切れた線を膨張で橋渡し。**断片化するなら上げる**(旧「連結 closing」) |
| ④ なめらかさ | 曲率のノイズ抑制(旧「平滑化」) |
| 校正(2点クリック) | 既知長さの2点→mm入力でスケール設定。**クリック中はカーソル周辺を隅のルーペで拡大表示**(緑の十字が中心画素)し、端点を精密に置ける |
| px/mm 直接入力 | スケール(px/mm)を数値で直打ち→「適用」(またはEnter)で設定。2点クリックの代わりに、既知のスケール値をそのまま入力できる。既に解析済みなら即座に 1/mm 表示へ反映 |
| **解析範囲トリム(縦棒)** | 下グラフの緑の縦棒を左右にドラッグ→端のノイズ区間を除外。除外部は灰色。中央値/R・カラースケール・縦軸・一括解析すべてに反映。ダブルクリックで全域リセット |
| グラフ: 曲率κ / 曲率半径R | 下グラフ・画像カラー・カラーバー・時系列グラフの縦軸を **κ(s)** と **R(s)=1/κ** で切替。R表示は「小さい=急な曲がり」を目立たせる反転カラーマップ&直線部の発散をパーセンタイルで抑制 |
| 符号付き(±) | ONで**符号付き曲率** κ = (x′y″−y′x″)/(…)^{3/2}(絶対値を取らない)。負値=曲がる向きを表し、S字などの**変曲点**が見える。両符号あるときは0中心の対称スケール＋発散配色(coolwarm)＋0基準線。OFFで従来の絶対値表示。CSV・中央値表示・時系列にも反映 |
| 解析 | 現フレームの曲率を計算・表示。失敗時は原因別ヒントを表示 |
| このフレームCSV | s, x, y, κ, R を書き出し |
| 全フレーム一括 | フレーム毎の中央曲率・半径を時系列CSV+グラフ化 |

## 検証結果（experiment_k20.mp4）

- フレーム個別解析で **R ≈ 199–200 px（κ ≈ 0.005 1/px）**、複数フレームで一致。
- 全動画一括(62点)でも中央 R ≈ 198 px、**クラッシュ0**。
- 物理的整合性: 曲げ開始後、送り量(弧長 150→680 px)が増えても半径は一定 ≈200 px。
  これは定モーメント曲げ（T≈M_p）で生じる**等曲率**と一致。

### 注意点
- ワイヤがほぼ直線の短いスタブ状態（曲げ開始前）では、曲率は本質的に不安定
  （短い直線区間の2階微分ノイズが支配的）。曲率が意味を持つのは実際に曲がってからの区間。
- 実寸(1/mm)が必要な場合は必ず校正すること。基準は定規・既知寸法の部品・
  ワイヤ径など、画面内で寸法が確実に分かるものを使う。
- 別動画では ROI と閾値の再調整を推奨（背景輝度・ワイヤ位置が変わるため）。

## 出力ファイル
- `curvature_frameNNN.csv` — 単一フレームの s, x, y, κ, R
- `curvature_timeseries.csv` — frame, time, 弧長, κ中央値, R中央値
- `annotated_frameNNN.png` — 曲率カラー中心線＋分布グラフ
